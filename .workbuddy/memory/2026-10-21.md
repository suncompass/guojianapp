## 项目结构分析（只读）

- 规模：lib 94 个 Dart 文件 33.5k 行；native/core 107 个非测试 Go 文件 24.1k 行 + 37 个测试文件 6.8k 行；Dart 测试 11.4k 行。
- 架构：Flutter 界面 → core_bridge.dart（工作 isolate 内做 JSON 编解码 + FFI）→ 单一导出 `DuanjuRequest`/`DuanjuFree` → Go 核心按 action 分发。iOS 走 DynamicLibrary.process，Android/Windows 分别加载 .so/.dll。
- 站源可见性唯一判定点：`native/core/app_build.go` 的 `nativeGreenSources`（红果 + 11 个绿色短剧源），Dart 侧 `SourceSite.values` 需与之逐条对应。
- 平台：Android 手机/Windows 第一优先，Android TV 第二，iOS 最后。画质增强链路仅 Windows 启用。
- 版本 0.3.6+2117，changelog 37 个文件。最近改动是红果 App 取流（去 video_platform、密钥双形态兼容、该请求跳过 X-Gorgon 签名）。
- 当前状态：整体回归自 2026-09-21 起暂停，绝大多数行为仍标"开发快照 / 待集中验收"。
- 发布链路：`scripts/finish_task.py` 同步源码到同级 `../guoapp`（已存在）并生成版本压缩包。

## 红果源失效修复（0.3.7）

用户反馈红果源完全不能使用，参考 zhoufuweigg/guoapp PR #12 修复。

**根因**：红果服务端升级了 `/novel/player/*` 的签名要求，在 X-Gorgon / X-Khronos 之外新增 X-Argus（Argus551）+ X-Ladon。缺这两个头不报错，而是返回 HTTP 200 + 空响应体。

**关键冲突**：0.3.6 走的是相反方向——认为上游只校验 Gorgon，故对取流请求跳过签名。该逻辑会主动删除 X-Argus / X-Ladon，正好命中失效原因，且 0.3.6 changelog 自记"未经本机复验"。PR 侧有完整实测表，故按 PR 方案改为补签名。

**实际改动**（PR 三处里只有一处是真缺口）：
- 新增 `native/core/provider_hongguo_player_sign.go`：signHongguoPlayerRequest + Argus/Ladon，与弹幕签名链路隔离（弹幕走 provider_hongguo_comment_sign.go，身份字段 3019/1611921764 不同）。
- `provider_hongguo_app.go`：非弹幕请求统一切到新签名，移除 hongguoSkipSignKey 分支。
- `provider_hongguo_native_media.go`：取流请求不再打 skipSign 标记。
- `provider_hongguo_sign.go`：删除 signHongguoRequest 与 prepareHongguoUnsignedRequest，Gorgon 逻辑并入新文件。
- `app_danmaku_test.go`：断言方向反转——player 请求现在**必须**带 X-Argus/X-Ladon。

**已领先上游、无需改动的两处**（重要，后续别重复改）：
- `app_stream.go` 播放列表判定已是修好形态：按 URL path 后缀判 .m3u8 + nativePlaylistPrefix 内容嗅探，不用整串 Contains(url,"hls")。
- 全平台已统一 media_kit/mpv，无 LunaExoPlayer；`demuxer-lavf-o` 的 decryption_key 对 Android 已生效。
  → CENC 密钥解密与 MP4 直链透传链路本就已具备，剩下只需验签。

**验证**：`go build ./...` 通过；`go vet` 仅剩既有 network_media.go:250 锁拷贝告警；红果/播放定向测试全绿。
