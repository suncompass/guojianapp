# 0.3.7：红果取流补 X-Argus / X-Ladon 签名，恢复失效的播放链路

红果源取流返回 HTTP 200 但响应体为空，播放无法进行。根因是红果服务端升级了 `/novel/player/*` 的签名要求：在原有 `X-Gorgon` / `X-Khronos` 之外新增 **X-Argus（Argus551）+ X-Ladon**。缺少这两个头的请求不报错，而是返回空响应体，因此表现为「取流失败」而不是「签名被拒」。

0.3.6 走的是相反方向：认为上游只校验 Gorgon、Khronos，故对该请求跳过签名。该判断未经本机复验（见 0.3.6 记录），而跳过逻辑会主动删除 X-Argus / X-Ladon，恰好命中本次失效原因。本版按上游 fork 的实测方案改回「补签名」。

## 变更

- **新增 `native/core/provider_hongguo_player_sign.go`**：`signHongguoPlayerRequest()` 保留原 Gorgon / Khronos / SS-STUB 逻辑并追加 X-Argus（protobuf 编码 + SM3 + Feistel）与 X-Ladon；身份字段按 novelread（aid=8662、7.3.5.32、v04.07.01-ml-android）填写，与弹幕签名链路隔离，两者不共用。
- **`provider_hongguo_app.go`**：非弹幕请求统一切到 `signHongguoPlayerRequest`；移除 `hongguoSkipSignKey` 上下文标记及其分支。
- **`provider_hongguo_native_media.go`**：取流请求不再打 `hongguoSkipSignKey` 标记，随请求链路走正常签名。
- **`provider_hongguo_sign.go`**：移除被取代的 `signHongguoRequest` 与 `prepareHongguoUnsignedRequest`，仅保留 `newHongguoDeviceID`。Gorgon 计算逻辑已并入新文件。
- **`app_danmaku_test.go`**：断言方向修正——player 请求现在**必须**带 X-Argus / X-Ladon，同时仍不得带 `Comment-Source`；弹幕请求继续要求四个签名头齐全且保持匿名低优先级。
- 版本号递增 `pubspec.yaml` 至 `0.3.7+2124`。

## 未改动的上游修复项

上游 PR 还包含两处修复，本项目代码已经是修好的形态，无需重复改动：

- `app_stream.go` 播放列表判定：本项目已按 URL 路径后缀与响应内容嗅探（`nativePlaylistPrefix`）判定 HLS，不再用整串 `Contains(url, "hls")` 匹配，带 CENC 密钥的 MP4 直链不会被误判为播放列表。
- `player_screen.dart` Android 端播放器：本项目已全平台统一使用 media_kit / mpv（无 LunaExoPlayer 分支），`demuxer-lavf-o` 的 `decryption_key` 注入对 Android 同样生效，CENC 加密 MP4 可解。

## 验证边界

本机 Go 1.27 可用。`go build ./...` 通过；`go vet ./...` 仅剩既有的 `network_media.go:250` 锁拷贝告警（与本轮无关，0.3.6 已记录）。红果与播放链路定向测试（`Hongguo|Stream|Decode|Playback`）全部通过。

完整套件有 3 个失败：`TestNativeLibraryImportRejectsForeignVersions`、`TestMigrationRejectsContainmentAndSymbolicLinks`、`TestLegacyAnonymousCatalogAndSessionReuse`。已用 `git stash` 对比基线，确认这三个在改动前的同一提交上同样失败，属既有问题，与本轮无关。

**未执行真机播放验证**：未在设备上确认红果取流是否真正返回可播媒体，CENC 密钥解密后能否正常起播仍需实测。本版继续标为开发快照。
