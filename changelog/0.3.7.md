# 0.3.7：播放请求走无签名流程并使用独立设备标识

按用户提供的改动说明实施。播放取流不再走签名链路，改用独立的播放设备标识，避免复用剧库缓存里已被标记的设备 ID。

## 基线说明

本次从 `934944c`（0.3.6）回溯后实施。此前 `dfe27f3` 与 `6413683` 曾尝试过两条不同路线（先补 `X-Argus`/`X-Ladon` 签名，后改为全平台无签名），均未做真机验证，本次不再保留。回溯前的状态已存为 `backup/pre-rollback-6413683` 标签，需要时可取回。

## 变更

**1. 播放请求只保留公共头（`native/core/provider_hongguo_app.go`、`provider_hongguo_sign.go`）**

- 新增 `hongguoPlaybackKey` 上下文标记。
- 新增 `prepareHongguoPlaybackRequest`：显式清除 `X-Gorgon`、`X-Khronos`、`X-Argus`、`X-Ladon`、`X-SS-STUB`，仅设置 `X-SS-Req-Ticket` 与 `X-TT-Request-Tag: t=0;n=0`。
- 与已有的 `prepareHongguoUnsignedRequest` 分开：后者仍会设置 `X-SS-STUB`，而播放请求不得携带该头，因此两者不能合流。
- 分发改为四路：播放走公共头、弹幕走弹幕签名、既有 `hongguoSkipSignKey` 保持原行为、其余走 `signHongguoRequest`。
- Query 统一补`ts`（秒级）与 `_rticket`（毫秒级）。

**2. 随机播放设备标识（`native/core/provider_hongguo_app.go`）**

- `hongguoAppClient` 增加独立的 `playerDeviceID`、`playerInstallID`、`playerCID`。
- 三者在 `hongguoOnce` 初始化时随机生成，属于进程启动期标识，不写入 `state`，因此不会被剧库缓存持久化，避免复用已被标记的设备 ID。
- 播放请求以这两个标识覆盖 `device_id` 与 `iid`，并附加 `cid`。

**3. 接口路径切回（`native/core/provider_hongguo_native_media.go`）**

- 取流入口由 `/novel/player/video_model/v1/` 改为 `/novel/player/multi_video_model/v1/`。
- 请求打上 `hongguoPlaybackKey` 标记，取代原先的 `hongguoSkipSignKey` 标记。
- 响应解析增加平铺结构兜底：`video_model` 为空或缺少 `video_list` 时，从 `data` 上的平铺字段读取，避免换路径后取不到清晰度列表。

**4. 单元测试（`native/core/provider_hongguo_app_test.go`，新增）**

- `TestHongguoPlaybackRequestIsUnsignedWithIsolatedDevice`：断言请求路径为 `/novel/player/multi_video_model/v1/`，不包含 `X-Gorgon`、`X-Khronos`、`X-SS-STUB`、`X-Argus`、`X-Ladon`、`Comment-Source`，携带 `X-TT-Request-Tag` 与 `X-SS-Req-Ticket`，Query 含 `ts`、`_rticket`、`device_id`、`iid`、`cid`，且播放标识与剧库标识不同并确实用于该请求。
- `TestHongguoCatalogRequestKeepsSignature`：断言目录与详情请求仍携带 `X-Gorgon`、`X-Khronos`、`X-SS-STUB` 且不带 `cid`，确认改动只作用于播放链路。
- `TestHongguoPlaybackDeviceIdentityIsNotPersisted`：断言播放标识不出现在剧库缓存快照中。

版本号递增 `pubspec.yaml` 至 `0.3.7+2124`。

## 验证边界

`go build ./...` 通过。`gofmt` 已格式化本轮编辑的四个文件。红果相关测试全部通过，含三个新增用例与既有的弹幕并发、备用地址、清晰度用例。

完整套件仍有 3 个失败（`TestNativeLibraryImportRejectsForeignVersions`、`TestMigrationRejectsContainmentAndSymbolicLinks`、`TestLegacyAnonymousCatalogAndSessionReuse`），与历史记录一致，属基线固有失败，与本轮无关。
