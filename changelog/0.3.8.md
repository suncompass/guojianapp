# 0.3.8：播放请求走无签名流程并使用独立设备标识

按用户提供的改动说明实施。播放取流不再走签名链路，改用独立的播放设备标识，避免复用剧库缓存里已被标记的设备 ID。

## 变更

**1. 播放请求无签名流程（`native/core/provider_hongguo_app.go`）**

- 新增 `hongguoPlaybackKey` 上下文标记。
- 播放请求仅添加公共请求头（`X-SS-Req-Ticket`、`X-TT-Request-Tag: t=0;n=0`、`Accept` 等），并在 Query 拼装 `ts` 与 `_rticket`。
- 新增 `prepareHongguoPlaybackRequest`（`native/core/provider_hongguo_sign.go`）：显式清除 `X-Gorgon`、`X-Khronos`、`X-SS-STUB`、`X-Argus`、`X-Ladon`，完全不携带签名头。

**2. 随机播放设备标识（`native/core/provider_hongguo_app.go`）**

- `hongguoAppClient` 增加独立的 `playerDeviceID`、`playerInstallID`、`playerCID`。
- 三者在 `hongguoOnce` 初始化时随机生成，属于进程启动期标识，不写入 `state`，因此不会被剧库缓存持久化，避免复用已被标记的设备 ID。

**3. 接口路径切回（`native/core/provider_hongguo_native_media.go`）**

- 取流入口由 `/novel/player/video_model/v1/` 改为 `/novel/player/multi_video_model/v1/`。
- 请求带上 `hongguoPlaybackKey` 标记。
- 响应解析增加平铺结构兜底：`video_model` 为空或缺少 `video_list` 时，尝试从 `data` 上的平铺字段读取，避免换路径后取不到清晰度列表。

**4. 单元测试同步（`native/core/provider_hongguo_app_test.go`，新增）**

- `TestHongguoPlaybackRequestIsUnsignedWithIsolatedDevice`：断言请求路径为 `/novel/player/multi_video_model/v1/`，不包含任何签名头（`X-Gorgon`、`X-Khronos`、`X-SS-STUB`、`X-Argus`、`X-Ladon`、`Comment-Source`），Query 含 `ts`、`_rticket`、`device_id`、`iid`、`cid`，且播放标识与剧库标识不同、并确实用于该请求。
- `TestHongguoCatalogRequestKeepsSignature`：断言目录与详情请求仍携带 `X-Gorgon`、`X-Khronos`、`X-Argus`、`X-Ladon`，确认改动只作用于播放链路。
- `TestHongguoPlaybackDeviceIdentityIsNotPersisted`：断言播放标识不出现在剧库缓存快照中。

版本号递增 `pubspec.yaml` 至 `0.3.8+2131`。

## 验证边界

`go build ./...` 通过。`gofmt` 已格式化本轮编辑的四个文件。红果相关测试全部通过，含三个新增用例与既有的弹幕并发、备用地址、清晰度用例。

完整套件仍有 3 个失败（`TestNativeLibraryImportRejectsForeignVersions`、`TestMigrationRejectsContainmentAndSymbolicLinks`、`TestLegacyAnonymousCatalogAndSessionReuse`），与 0.3.7 记录的基线固有失败一致，已用 `git stash` 对比确认与本轮无关。

**未执行真机取流验证**：新路径 `/novel/player/multi_video_model/v1/` 的实际响应结构与本轮兜底解析是否吻合，仍需实测确认。签名头已按说明全部移除，若上游仍要求签名则取流会继续返回空响应体。真机验证前继续标为开发快照。
